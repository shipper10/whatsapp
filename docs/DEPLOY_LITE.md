# تشغيل الوضع الخفيف (Baileys) على Render

للمقارنة بين الوضعين: [`MODES.md`](MODES.md). هنا خطوات التشغيل الكاملة بلا بطاقة بنكية.

## ما تحتاجه
1. حساب **GitHub** يحوي هذا المستودع.
2. قاعدة **PostgreSQL مجانية** (Neon أو Supabase).
3. حساب **Render** (الخطة المجانية Web Service).
4. رقم واتساب مخصص للبوت (يمكن شريحة احتياطية).
5. مفاتيح **تيليجرام** وجلسة دخول ([`TELEGRAM_SETUP.md`](TELEGRAM_SETUP.md)).
6. اختياري: مفتاح **Google Drive** ([`DRIVE_SETUP.md`](DRIVE_SETUP.md)).

## 1. قاعدة البيانات
- **Neon** (neon.tech): أنشئ مشروعًا وانسخ رابط الاتصال `postgresql://...?sslmode=require`.
- **Supabase**: Project settings ← Database ← Connection string. استعمل نسخة **Session pooler** إن تعذّر الاتصال المباشر.
- المساحة المجانية (~0.5GB) كافية لأن البوت يحفظ بيانات وصفية فقط.
- ينشئ البوت الإضافتين `pg_trgm` و`unaccent` بنفسه.
- **Supabase** يوقف المشروع المجاني بعد نحو أسبوع بلا نشاط؛ البوت يقرأ من قاعدته كل بضع دقائق فلا يُعدّ خاملًا (راجع «إبقاء الخدمة مستيقظة»).

## 2. إنشاء الخدمة على Render
**الطريقة الأسهل:** *New ← Blueprint* واختر المستودع؛ يقرأ `render.yaml` فيجهّز كل شيء ما عدا القيم السرية.

**يدويًا:** *New ← Web Service* من المستودع، ثم:
- Runtime: Node، Node version: **22**
- Build command: `npm ci && npm run build`
- Start command: `npm start` (يطبّق ترقيات قاعدة البيانات ثم يشغّل البوت)
- Plan: Free، Health check path: `/healthz`

## 3. متغيرات البيئة
اضبطها في Render ← Environment (لا تضعها في المستودع أبدًا):

| المتغير | القيمة |
|---|---|
| `NODE_ENV` | `production` |
| `WHATSAPP_PROVIDER` | `baileys` |
| `DATABASE_URL` | رابط Neon/Supabase |
| `DB_POOL_MAX` | `3` |
| `ADMIN_HTTP_TOKEN` | نص عشوائي طويل (16 حرفًا فأكثر)؛ يحمي صفحة الربط **ولوحة الويب** (`/admin/panel`) |
| `ADMIN_IDS` | رقمك بعد الربط، مثل `2499xxxxxxxx@s.whatsapp.net` |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | من my.telegram.org |
| `TELEGRAM_CHANNEL` | اسم القناة، مثل `BahriMed` |
| `TELEGRAM_SESSION_STRING` | ناتج `npm run telegram:login` |
| `TEMP_FILE_DIR` | `/tmp/bot` |
| `GOOGLE_SERVICE_ACCOUNT_JSON_BASE64` | اختياري: مفتاح درايف بصيغة base64 |

بقية المتغيرات اختيارية: انظر `.env.example` و[`SETTINGS.md`](SETTINGS.md) (كل إعداد له متغير بيئة اختياري يحدد قيمته الابتدائية).

## 4. ربط واتساب (مرة واحدة)
1. افتح `https://<خدمتك>.onrender.com/admin/link?token=<ADMIN_HTTP_TOKEN>`؛ تظهر صورة QR وتتحدث وحدها.
2. على هاتف الرقم المخصص: واتساب ← الأجهزة المرتبطة ← ربط جهاز ← امسح الرمز.
   - لا تستطيع مسح شاشة هاتفك نفسه؟ اكتب الرقم (أرقام بكود الدولة) في النموذج أسفل الصفحة واضغط *Get pairing code*، ثم: واتساب ← الأجهزة المرتبطة ← **الربط برقم الهاتف** وأدخل الرمز.
3. عند ظهور «Linked» يُحفظ الدخول في PostgreSQL ولا يلزم مسح جديد بعد أي إعادة نشر.
4. ضع رقمك في `ADMIN_IDS` لتصير مشرفًا، ثم أعد النشر. جرّب إرسال `/status` للبوت على الخاص.

## 5. أول مزامنة
- تبدأ المزامنة تلقائيًا بعد التشغيل بثوانٍ وتتكرر كل 10 دقائق (قابل للتعديل بـ `sync.telegram.intervalMinutes` و`sync.drive.intervalMinutes`).
- لتشغيلها فورًا أرسل `/sync` (تعمل في الخلفية وتصلك رسالة عند الانتهاء، و`/status` يعرض تقدمها).
- بعد أول تشغيل يقرأ البوت الملفات المخزنة مرة واحدة ليتعرف على ألبومات تيليجرام.

## 6. إبقاء الخدمة مستيقظة (Render المجانية)
تنام الخدمة المجانية بعد ~15 دقيقة بلا زيارات. الحل مزدوج:
- **ذاتي:** يطلب البوت رابطه كل `keepalive.intervalMinutes` (الافتراضي 10 دقائق) عبر `RENDER_EXTERNAL_URL` الذي يضعه Render تلقائيًا، وفي كل مرة يقرأ قاعدة البيانات. على غير Render ضع `KEEPALIVE_URL`. القيمة 0 تعطّله.
- **UptimeRobot (احتياط):** Monitor من نوع *HTTP(s)*، الرابط `https://<خدمتك>.onrender.com/healthz`، كل 5 دقائق. لا تستعمل رابط `/admin/link`.
- حصة Render المجانية 750 ساعة تشغيل شهريًا، تكفي خدمة واحدة تعمل دائمًا في الحساب.

## 7. التحديث
ادفع التعديلات إلى فرع `main` (النشر التلقائي مفعّل افتراضيًا). ترقيات قاعدة البيانات تُطبَّق عند التشغيل.

## 8. حدود الاستضافة المجانية (مهم)
- الذاكرة 512MB تقريبًا: يحتاج كل نقل ملف مساحة مؤقتة بنحو **ضعف حجم الملف**، فاترك `delivery.concurrency` عند 1 للملفات الكبيرة، ولا تشغّل مزامنة ثقيلة أثناء إرسال ملفات ضخمة.
- حد الملف المرسل `delivery.maxAttachmentMb` (الافتراضي 300MB)؛ ما فوقه يصل روابط. واتساب نفسه يقبل مستندات حتى 2000MB لكن استضافتك لن تتحمل ذلك غالبًا.
- القرص مؤقت ويُمسح مع كل نشر، وهذا لا يضر لأن كل ما يهم في PostgreSQL.
