# حل المشاكل الشائعة

ابدأ دائمًا بـ `/status` (من رقم مشرف على الخاص) ثم سجلات الاستضافة (Render ← Logs، أو `docker compose logs -f bot`).

## البوت لا يرد
| السبب المحتمل | الحل |
|---|---|
| الخدمة نائمة (Render المجانية) | افتح `https://<خدمتك>.onrender.com/healthz`؛ فعّل UptimeRobot والإبقاء الذاتي (`keepalive.intervalMinutes`، [`DEPLOY_LITE.md`](DEPLOY_LITE.md) §6) |
| الرقم غير مرتبط أو خرج | افتح `/admin/link?token=…` وأعد الربط. إن ظهر في السجل «session replaced by another client» فهناك نسخة ثانية تعمل بنفس الدخول: أوقفها |
| (الوضع الكامل) سر الويب هوك لا يطابق | سجل البوت: «webhook rejected»؛ ثم سجل `openwa`؛ ويجب أن يحوي `SSRF_ALLOWED_HOSTS` القيمة `bot` |
| في مجموعة | يرد فقط عند `!`؛ تحقق من `group.mode` و`group.triggers` |
| وصلت لحد المعدل | انتظر قليلًا (`rateLimit.perParticipantPerMinute`) |

الخدمة تتوقف وتحتاج إيقافًا وإعادة بناء من Render: غالبًا **نفاد الذاكرة** (512MB) أثناء مزامنة أو إرسال ملف كبير. أبقِ `delivery.concurrency` عند 1، وقلّل `delivery.maxAttachmentMb`، ولا تشغّل مزامنة أثناء إرسال ملفات ضخمة، وأرسل لي آخر أسطر السجل قبل التوقف إن تكرر.

## المزامنة
- **`/status` يعرض stale أو خطأ:** `Telegram session is not authorized` ← أعد `npm run telegram:login` وحدّث `TELEGRAM_SESSION_STRING`.
- **خطأ مصدر درايف:** شارك المجلد مع بريد حساب الخدمة (Viewer) — [`DRIVE_SETUP.md`](DRIVE_SETUP.md).
- **بدا أن البوت متوقف أثناء المزامنة:** المزامنة تعمل بالخلفية وتصلك رسالة عند الانتهاء؛ `/status` يعرض ما يجري ومنذ كم.
- **ملفات أو ألبومات جديدة لا تظهر:** تحقق من آخر مزامنة، وتذكّر أن الأرقام 【ن】 تأتي من نص الفهرس نفسه في القناة.
- **ألبومات قديمة تظهر كملفات منفصلة:** شغّل `/sync telegram` مرة بعد التحديث؛ يقرأ الملفات المخزنة مرة واحدة ليتعرف على الألبومات.

## الملفات والإرسال
| العَرَض | السبب والحل |
|---|---|
| تصل **روابط فقط** | الحجم فوق `delivery.maxAttachmentMb`، أو النوع غير مسموح (`delivery.allowedMediaTypes`)، أو `delivery.sendAttachment=false`، أو فشل التنزيل/الإرسال (يذكر الرد السبب) |
| `/set delivery.allowedMediaTypes pdf` حجب كل شيء | كان السبب أن `pdf` لا تساوي `application/pdf`؛ صُحِّح. الآن تُقبل كلمات وامتدادات وMIME ومسافات |
| ملف تالف أو ناقص | يقارن البوت حجم التنزيل بحجم المصدر ويعيد التنزيل مرة؛ إن اختلف يرسل روابط بدل ملف قد يكون تالفًا |
| الإرسال بطيء أو متأخر | الملفات الكبيرة تأخذ وقتًا في الرفع؛ تابع رسالة الحالة (نسبة/سرعة/وقت). إن ظهر «لا يتقدم منذ N ث» فالاتصال بطيء أو متوقف |
| شريط التقدم لا يتحدث | الوضع الكامل (OpenWA) لا يدعم تعديل الرسائل؛ أو توقف التعديل عمدًا (حد 40 تعديلًا و~14 دقيقة، لتجنب ما يشبه الإزعاج). النتيجة النهائية تصل دائمًا |
| تصل روابط فقط مع أن الملف صغير ومسموح | قد تكون المساحة الحرة أقل من `delivery.minFreeDiskMb` (انظر `/status`). خفّض الإعداد أو حرّر مساحة؛ الطلبات الكبيرة المتزامنة ينظمها `delivery.maxInflightMb` |
| الفيديو الأكبر من 16MB لا يصل | حد 16MB للصوت فقط؛ الفيديو الأكبر يصل مستندًا حتى `delivery.maxAttachmentMb` (كان خطأ سابقًا يعامل mp4 كصوت وصُحِّح) |
| الملف يصل أسرع في المرة الثانية | طبيعي: كاش إعادة الإرسال (`delivery.cacheHours`). إن لم يعمل لسبب ما يعود البوت للإرسال العادي تلقائيًا |
| ألبومات تصل ملفًا واحدًا | حدّث وشغّل `/sync telegram` (انظر أعلاه) |

## الصوت
| العَرَض | الحل |
|---|---|
| «This audio is not available…» للملفات الأكبر من 16MB | حد واتساب. يقسّم البوت الصوت تلقائيًا إلى أجزاء (`delivery.largeAudioMode split`)؛ للملف الكامل استعمل الروابط، أو جرّب `/set delivery.largeAudioMode document` ليصل كاملًا مرفقًا |
| الجزء الأول يتوقف بعد مدة | كان سببه ترويسة mp3 (وسم ID3 + إطار Info) تدّعي مدة الملف كله؛ تُحذف الآن من كل جزء. وفي opus يُعاد حساب مواضع الصفحات |
| ملف opus لا يعمل أبدًا | قد يحمل صورة غلاف ضخمة داخل الوسوم؛ يُنظَّف الرأس تلقائيًا قبل الإرسال |
| «sent in an unusual format… may be dangerous» | امتداد `.opus` غير مقبول كمرفق؛ يُرسل Ogg/Opus باسم `.ogg` |
| ما زال ملف معين لا يعمل | جرّب `/set delivery.audioMode document` (يصل مرفقًا) أو `/set delivery.largeAudioMode links` (روابط فقط) أو `/set delivery.opusAsMp3 true` (لملفات opus: يُرسل مرفقًا باسم mp3)، وأرسل لي نوعه وحجمه |
| صيغة m4a كبيرة | لا تُقسَّم؛ تصل برابط |

حدود واتساب المعروفة: صوت/فيديو كرسالة مباشرة حتى 16MB، صورة حتى 5MB، مستند حتى 2000MB (حسب التطبيق؛ واجهة الأعمال الرسمية تضع 100MB للمستندات).

## اللوحة والإشعارات
| العَرَض | السبب والحل |
|---|---|
| `/admin/panel` يعطي 404 | `ADMIN_HTTP_TOKEN` غير مضبوط (16 حرفًا فأكثر) |
| اللوحة تطلب الرمز كل مرة | الكوكي لا يُحفظ: افتح الرابط بـ https، أو فعّل الكوكيز للموقع |
| لا تصلني تنبيهات المزامنة | `alerts.syncFailures=0`؟ أو رقمك ليس في `ADMIN_IDS` ولا مسجل بـ `/admin add`؟ أو واتساب نفسه غير متصل |
| المشتركون لا تصلهم إشعارات | `notify.enabled`؟ مرّت `notify.minIntervalHours`؟ أول مزامنة بعد التفعيل لا ترسل (تضبط البداية فقط) |
| كتبت اسم مادة ولم يفتح فهرسها | جرّب أول حروف الاسم (`anat`)؛ البوت يتسامح مع الأخطاء والتصحيح الإملائي يبدأ من 4 أحرف (الكلمة الأقصر يجب أن تُكتب صحيحة أو أولها). أسماء الفهارس تُقرأ من القناة، فتأكد من الاسم في `/status` أو بعد `/sync`. الأسماء العربية لم تعد مدعومة |

## واتساب والحظر
- استعمل رقمًا مخصصًا؛ هذا عميل غير رسمي والخطر مقبول لكنه قائم.
- حافظ على فاصل الإرسال `whatsapp.minSendGapMs`، ولا ترفع حدّ الدفعات كثيرًا.
- لا تُشغّل نسختين على نفس الرقم.

## المكتبات: هل التحديث يحل المشاكل؟
مكتبة Baileys الحالية `7.0.0-rc14` هي آخر إصدار منشور (يوليو 2026). المكتبة تشفّر وترفع فقط؛ تشغيل الصوت يتم داخل تطبيق واتساب على الهاتف، لذلك مشاكل الصوت تعالج بتجهيز الملف لا بتحديث المكتبة. راجع `npm outdated` دوريًا وجرّب أي ترقية على نسخة تجريبية قبل الإنتاج.
